When handling any reply, always follow this order before drafting:

1. Check memory files for relevant rules and feedback
2. Read `1. Departments/reply-management/SKILL_Reply-Management.md` as the process framework
3. Read `1. Departments/reply-management/CONTEXT_Replies.md` for tone and formatting rules
4. Read the client file (`clients/[slug].md`) for offer details, tone, and Calendly link
5. Read the full thread history to avoid repeating info and to understand the relationship so far
6. Then draft — with human touch. The reply must sound like a real person who read the full conversation, not a template filler.

**Why:** Drafts come out generic and robotic when context is skipped. Reading the full thread and all files is what makes the reply feel like it came from a human who gives a shit.

**How to apply:** No exceptions. Every single reply, every time. Generic = wrong.
